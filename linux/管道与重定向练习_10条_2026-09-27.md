## 零、开工前必读：三个坑

### 坑 1：`>` 是覆盖，`>>` 是追加

```bash
ls /etc >  /tmp/a.txt    # 新建；如果文件已存在，先清空再写！
ls /var >> /tmp/a.txt    # 在后面追加，不动原内容
```

**用 `>` 覆盖了重要文件 = 内容直接消失。** 这是重定向第一大事故。
练习时统一往 `/tmp/` 写，绝不往 `/etc`、`/var` 这类系统目录写。

### 坑 2：`|` 只传标准输出，错误不走管道

```bash
cat 不存在的文件 | wc -l     # 输出 0，因为报错信息没进管道
cat 不存在的文件 |& wc -l    # 加上 |&（等于 2>&1 |）才能把错误也送进去
```

### 坑 3：`grep` 找不到时"不报错"

它在终端上看着像正常执行完，其实是**退出码 1**（找到了是 0）。脚本里别拿它当"出错"判断。

## 一、10 条组合命令（按顺序敲，难度递增）

### 🟢 入门三条

| # | 命令 | 干什么 |
|---|---|---|
| 1 | `ls /etc \| wc -l` | 数 /etc 下有多少个条目 |
| 2 | `cat /etc/passwd \| wc -l` | 数系统里有多少个用户 |
| 3 | `cat /etc/passwd \| grep bash` | 筛出真正能用 bash 登录的用户 |

**要点**：`|` 左边命令的输出，成了右边命令的输入。所以 `ls /etc` 原本是一列文件名，`wc -l` 数行数就是数条目数。

### 🟡 进阶四条

| # | 命令 | 干什么 |
|---|---|---|
| 4 | `cat /etc/passwd \| grep bash \| wc -l` | 三个串起来：筛完再数 |
| 5 | `cat /etc/passwd \| grep -v nologin \| wc -l` | `-v` = 反向筛选，排除掉不能登录的 |
| 6 | `ls /etc \| sort \| head -10` | 排序后取前 10 个 |
| 7 | `ls /etc \| sort \| tail -5` | 排序后取后 5 个 |

**关键理解**：`head` 和 `tail` 的作用**完全取决于前面有没有排序**。
- `ls /etc | head -10` → **随便** 10 个（顺序是系统给的）
- `ls /etc | sort | head -10` → 字母序**最小**的 10 个 ← 这才是"前 10"

### 🔵 实战三条

| # | 命令 | 干什么 |
|---|---|---|
| 8 | `history \| grep mysql \| wc -l` | 数你一共敲过多少条 mysql 命令 |
| 9 | `history \| grep mysql \| tail -5` | 看最近 5 条 mysql 相关命令 |
| 10 | `systemctl status mysqld \| grep Active` | 从一大坨服务状态里**只摘出关键那行** |

**第 8 条挺有意思** —— 能看出你这两周到底敲了多少遍。猜猜是多少？

**第 10 条才是管道的日常用法**：命令输出几十行你只关心一行，用 `grep` 摘出来。
照这个思路可以自己试：`systemctl status mysqld | grep -i "error"`

### 🟣 综合挑战

```bash
ls -l /var/log | sort -k5 -n | tail -5
```
找出 `/var/log` 目录里**最大的 5 个文件**。

拆解：
- `ls -l` 长格式输出，**第 5 列是文件大小**
- `sort -k5` 按第 5 列排序，`-n` 表示按**数值**排（不然 "9" 会排在 "100" 后面）
- `tail -5` 取最后 5 个 = 最大的 5 个

> ⚠️ `ls -l` 第一行是 `total xxx`，只有一个字段，排序时会排在开头，看着有点碍眼。
> 想干净可以加一步：`ls -l /var/log | grep -v "^total" | sort -k5 -n | tail -5`

## 二、4 条重定向专项

| # | 命令 | 练什么 |
|---|---|---|
| 11 | `ls /etc > /tmp/etc_list.txt` | **输出重定向**：结果写进文件，屏幕上什么都不显示 |
| 12 | `ls /var/log >> /tmp/etc_list.txt` | **追加重定向**：加在文件末尾，前一次的内容还在 |
| 13 | `wc -l < /etc/passwd` | **输入重定向**：把文件内容"喂"给命令，而不是用参数 |
| 14 | `systemctl status mysqld > /tmp/svc.txt 2>&1` | **正确 + 错误一起存**（`2>&1` 的意思：把错误流并到标准输出流） |

### 验证方法

```bash
cat /tmp/etc_list.txt        # 看第 11、12 条的结果
wc -l /tmp/etc_list.txt      # 数一数有几行，应该是两次 ls 的总和
```

### ⭐ `2>&1` 为什么这么写

三个"流"各有编号：

| 编号 | 名称 | 内容 |
|---|---|---|
| `0` | 标准输入 stdin | 命令读的东西 |
| `1` | 标准输出 stdout | 正常结果 |
| `2` | 标准错误 stderr | 报错信息 |

`2>&1` 读作"把 2 号流重定向到 1 号流去"——**让错误信息也混进正常输出里，一起被写进文件**。

## 三、命令选项速查

| 命令 | 常用选项 | 含义 |
|---|---|---|
| `grep` | `-i` | 忽略大小写 |
| | `-v` | 反向（不要匹配的行） |
| | `-n` | 显示行号 |
| | `-c` | 只输出匹配的**行数**（替代 `\| wc -l`） |
| | `-r` | 递归搜目录 |
| `wc` | `-l` | 行数（最常用） |
| | `-w` | 单词数 |
| | `-c` | 字节数 |
| `sort` | `-n` | 按数值排（不加则按字典序，"9" > "100"） |
| | `-r` | 倒序 |
| | `-u` | 去重 |
| | `-k5` | 按第 5 列排 |
| `head` / `tail` | `-n 10` 或 `-10` | 取前/后 10 行 |
| | `tail -f` | **持续跟踪**文件新增内容（看日志必备，`Ctrl+C` 退出） |
